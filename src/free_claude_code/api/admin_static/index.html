      Purpose

      Free Claude Code (FCC) is an independent, open-source local proxy and Admin UI that connects coding agents such as Claude Code, Codex, Pi, OpenCode, Cline, Hermes, Aider, and more to dozens of ToS-friendly AI providers — free, paid, subscription, and local — from a single place.

      • Where it runs: on your own machine, as a local server.
      • What it gives you: one model catalog for many agents, automatic fallback across providers, and live-browser Code sessions.
      • What it is not: an Anthropic product. FCC is not affiliated with or endorsed by Anthropic. “Claude” and “Claude Code” are trademarks of Anthropic.

      Free-tier availability and limits are controlled by each provider and may change at any time. FCC follows provider terms and removes integrations when they stop being allowed.

      How it works

      Agents normally talk to a single vendor API. FCC inserts a local proxy between your agent and the providers you choose:

      1. You start fcc-server. It binds the Admin UI and proxy to http://127.0.0.1:8082.
      2. On the Providers page you add API keys and pick a model (MODEL).
      3. Your agent is pointed at the proxy URL and token, so it discovers only your chosen models.
      4. FCC translates the agent’s Anthropic/OpenAI-style calls to the provider’s API, then streams the response back — tools, thinking, and images intact.
      5. If a provider fails after retries, FCC automatically retries your next configured model without interrupting the turn.

      The Admin UI and proxy are local-only by default. Enable Proxy Authentication to require a bearer token.

      Run it step by step

      1. Prerequisites

      • Git
      • Python 3.14+ (recommended via uv below)
      • uv — the project’s package manager

      2. Install uv (if missing)

      Windows PowerShell:

      powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"

      macOS / Linux:

      curl -LsSf https://astral.sh/uv/install.sh | sh

      3. Clone the repository

      git clone https://github.com/Alishahryar1/free-claude-code.git
cd free-claude-code

      4. Install the pinned Python 3.14

      uv python install 3.14.0

      5. Create the environment and install dependencies

      uv sync

      6. Start the server

      uv run fcc-server

      Keep this terminal open. After startup, the Admin UI opens at http://127.0.0.1:8082/admin. On Windows and macOS the desktop launcher adds a tray / menu-bar icon.

      7. Configure a provider

      1. Open the Admin UI and find your provider below in Provider examples.
      2. Generate an API key with the Get key button on the provider card.
      3. Paste the key into its field, pick a model, click Apply.

      8. Run a coding agent

      Each agent has a launcher (most still require that agent’s own CLI to be installed):

      fcc-server   # keep running
fcc-claude   # Claude Code
fcc-codex    # Codex
fcc-opencode # OpenCode
fcc-pi       # Pi
fcc-cline    # Cline
fcc-aider    # Aider

      You can also open Code sessions in the browser UI without installing any agent CLI.

      Connecting clients

      For terminal use, just run the matching fcc-* launcher after fcc-server. For editors, point each client at the proxy:

  { "name": "ANTHROPIC_BASE_URL", "value": "http://localhost:8082" },
  { "name": "ANTHROPIC_AUTH_TOKEN", "value": "freecc" },

      Match the port and token to this Admin UI. Restart the client or reload the extension after changing the model or provider.

      Troubleshooting

      The server does not start / “port already in use”

      Another FCC instance (or process) is holding 8082. Stop it, or change PORT in Admin settings and restart.

      The agent still asks me to log in

      Claude Code caches an onboarding flag. Merge the following into %USERPROFILE%\.claude.json (Windows) or ~/.claude.json (macOS/Linux) and restart: 

      { "hasCompletedOnboarding": true }

      A model is missing from the dropdown

      Enter the exact slug manually: <provider-id>/<model-id>, e.g. groq/llama-3.3-70b-versatile.

      Local provider is not reachable

      Start the local server first (ollama serve, LM Studio’s server, llama-server), confirm its URL, and use enough context for the agent’s system prompt and tool definitions.

      “The provider rejected this API key”

      The key is wrong or expired. Generate a fresh key on the provider’s page and re-Apply. Restart the agent to refresh its model picker.

      Something else

      Check the server terminal output, then report issues at the project issue tracker.

      Consistency

      • Run one fcc-server at a time; several agents share its proxy and model catalog.
      • The proxy URL (http://127.0.0.1:8082) and token (freecc) must match across every client configuration.
      • After connecting an account, changing providers, or changing models, restart the already-running agent so its model picker refreshes.
      • Model-tier routing (MODEL_OPUS, MODEL_SONNET, MODEL_HAIKU, MODEL_FABLE) lets each Claude tier use a compatible provider individually.

      Uninstall

      Stop every running FCC command first, then run the matching uninstaller from the scripts/ directory. It removes FCC and ~/.fcc/ but keeps uv, Python, and your installed coding agents.

      Maintain yourself

      • Keep the repository gated on Python 3.14 (see pyproject.toml).
      • Run uv run ruff check, uv run ty check, and uv run pytest before contributing; see CONTRIBUTING.md.
      • Version bumps in pyproject.toml require a matching uv lock update.
